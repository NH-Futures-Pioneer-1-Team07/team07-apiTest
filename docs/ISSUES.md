## 3. 상세

### NH-001 국내_차트(분) `req_qty` 상한 2000

- 현상: `req_qty` 를 1000, 2000, 2001, 3000, 9999로 요청 → 2000 초과는 오류나 안내 없이 2000건으로 잘림. `nxt_key` 로 이어 받기는 정상
- 명세: 「기본 300건 (최대 9999건)」. 로컬 문서도 아직 9999로 되어 있음. 해외_차트(분)도 같은 표기
- NH 답변 (10-26): 모의·실전 모두 2000건까지가 맞음. 담당 부서에 전달
- NH 답변 (11-06, NH-005 답변 중): 「최대 9999건」 표기를 실제 한도에 맞게 수정함
- 남은 확인: 웹 가이드에서 국내·해외 분봉 표기가 실제로 바뀌었는지. 해외 분봉, 국내·해외 일봉의 실제 상한이 얼마인지는 아무도 확인하지 않음

### NH-002 접근토큰 `expires_in` 타입 (우리 팀 제보)

- 현상: 명세는 String, 실제 응답은 숫자 `86400`
- NH 답변 (10-26): 모의·실전 모두 숫자. 서버는 그대로 두고 명세를 Number로 고칠 예정
- 테스트 반영: 숫자를 정상으로 판정하고, 명세가 바뀌면 보정 규칙을 지움

### NH-003 국내_주문내역 평균체결가격 0

- 현상: 전량체결 주문의 `occurs1_avg_exec_pric` 가 0
- NH 답변 (10-28): 미사용 필드. `occurs1_avg_exec_pric`, `occurs1_per_exec_qty`, `occurs1_ptt_exec_cnt` 는 문서에서 제거 예정
- 사용 규칙: 체결가는 `occurs1_exec_pric`, 보유 포지션 평균단가는 잔고 조회(`domestic_open-interest`)의 `occurs1_avg_pric`
- 테스트 반영: 세 필드는 값 검증에서 제외

### NH-004 해외_현재가 잘못된 거래소 코드

- 현상: `FHKEX` + MHIX26 → HTTP 200, 오류 없음, 모든 칸이 빈 1줄. 올바른 `FHKE` 는 정상, 없는 종목은 400 ETR029
- 원인: 장운영정보 거래소명 `HKEX` 앞에 F를 붙여 코드를 만듦. 명세 설명도 「선물/옵션 + 거래소코드, 예) CME 선물 : FCME」라서 이렇게 만들기 쉬움
- NH 답변 (11-04): 조회용 거래소 코드는 종목 마스터 파일 3번째 칸(ExchName) 값을 그대로 쓸 것. 잘못된 거래소 코드에 빈 줄을 주는 동작은 내부 확인 중
- 남은 확인: 서버 동작이 바뀌는지 회귀 확인. 해외 호가·차트·품목세부 같은 다른 해외 조회 API도 같은지는 확인하지 않음 (같다면 새 제보 대신 NH-004에 추가)

### NH-005 해외_차트(분) 마지막 페이지 `nxt_key`

- 현상: 마지막 페이지의 `nxt_key` 가 9로만 채워진 32자리 → 이 값으로 다시 요청하면 첫 페이지가 다시 옴
- NH 답변 (11-06): 9로만 된 키는 기본값 `99999999` 와 같게 처리됨. 응답 `nxt_key` 가 9로만 되어 있으면 마지막 페이지로 보고 멈출 것
- 남은 확인: 국내 차트(분·일), 해외 일봉도 같은 종료 규칙인지

### NH-006 해외_차트(일) 연결 일봉 데이터 품질

- 현상: 2001~2007년 미국 공휴일 봉 13개 가격 이상, 1998~2021년 시가·종가가 고가·저가 범위 밖인 봉 35~58%, 2022-06-24 → 2023-01-12 구간 누락 (ZN, ZF 모두)
- NH 답변 (11-06): 2022년 시스템 개편 전 모의 서버 과거 데이터 문제. 정확한 과거 데이터는 실전 서버에서 2022년 이후 구간으로 조회 권장. 연결 일봉은 거래량이 많은 월물 기준으로 이어짐
- 테스트 반영: 모의 서버 데이터 품질 검증은 2023-01-12 이후 구간만 대상. 그 이전 구간 이상은 다시 제보하지 않음

### NH-007 해외_차트(분) 시각 기준

- NH 답변 (11-06): `occurs1_ref_dt`, `occurs1_exch_tm` 은 거래소와 관계없이 KST. 실시간 체결(FA)과 맞출 때는 `ko_exec_tm`
- 원 제보는 받지 못함

### NH-008 국내_차트(분) 응답 지연

- 현상: 장중 21분 동안 157회 중 48회가 10초 안에 응답 없음, 최대 65.4초
- NH 답변 (11-12): 장중이라서가 아니라 오래된 날짜를 처음 조회할 때 느림. 최대 약 20초, 넘으면 504 `EGW032`. 한 번 받은 날짜와 최근 날짜는 0.1초대
- 사용 규칙: 읽기 제한 시간 30초, 504 `EGW032` 는 10초 기다린 뒤 같은 요청 재시도

### NH-009 해외_신규주문 장 마감 시간 5016

- 현상: 일요일 17:15 (CME 휴장) 주문 → 400 `5016` 「[거래소주문전송중 오류발생] 모듈 처리중 오류가 발생하였습니다.」, 주문 미접수
- NH 답변 (11-12): 장이 닫혀서 거절된 것. 모의 해외 주문은 07:00~24:00, 그 안에서도 거래소 장이 열려 있어야 함. CME는 토 07:00~월 08:00, 매일 07:00~08:00 (KST) 휴장
- 사용 규칙: 주문 전에 장 시간 확인. 5016이 오면 같은 주문을 반복해서 보내지 않음
- 남은 확인: 오류 메시지가 원인을 알려주지 않는 점은 답이 없음

### NH-010 모의 환경 장 종료 후 체결

- NH 답변 (11-13): 모의 환경은 장 종료 없이 24시간 주문·체결 가능. 장 종료 뒤에는 마지막 시세로 체결 가능한 가격이면 체결. 17:20 시장가 주문도 그렇게 체결됨
- 원 제보는 받지 못함. 17:20은 국내 정규장 종료(15:45) 이후라서 국내 주문 제보에 대한 답변으로 보이지만 확실하지 않음
- 남은 확인: NH-009(해외는 장 시간 밖이면 거절)와 범위가 다름. 국내만 24시간인지 확인 필요

### NH-011 국내_신규주문 거래소 접수 지연

- 현상: 15:31:00 주문 응답 정상 → 5초간 「미접수」 → 15:31:30 접수·체결. 평소는 0.2초대
- NH 답변 (11-13): 모의 서버가 가끔 불안정. 주문 응답이 정상이면 주문은 들어간 것
- 사용 규칙: 「미접수」를 실패로 보지 않고, 주문내역에서 접수·체결·거부가 확인될 때까지 기다림

### NH-012 해외_현재가 여러 종목 요청

- 현상: `Iccurs1` 에 2종목 → HTTP 200, 본문이 빈 문자열 (JSON 아님)
- NH 답변 (11-17): 한 번에 한 종목만. 명세는 확인해 보겠음
- 참고: 로컬 명세의 `Iccurs1` 배열 길이는 1
- 사용 규칙: 해외 현재가는 종목마다 따로 요청

### NH-013 해외_예수금조회 선택 항목 빈 문자열

- 현상: `"biz_dt": ""` → 400 `ETR018`. 키를 빼면 당일 기준 정상
- NH 답변 (11-17): 항목이 있으면 YYYYMMDD 형식으로 검사함. 날짜를 지정하지 않으려면 키 자체를 뺄 것
- 사용 규칙: 선택 항목은 빈 문자열 대신 키를 뺌. 다른 API도 같은 방식으로 검사할 가능성이 높음

## 5. 중복 방지와 다음 테스트 방향

### 5.1 다시 하지 않을 것

- 위 13건의 현상을 새로 탐색하는 테스트. 각 건은 **회귀 케이스 1개**로만 유지하고 `issue: NH-00X` 를 붙인다
- 회귀 케이스의 기대값은 NH가 설명한 현재 동작이다. 결과가 바뀌면 "동작 변경"으로 알리고, 새 오류로 보지 않는다
- 모의 서버 2022년 이전 과거 데이터 이상 제보

### 5.2 아직 아무도 확인하지 않은 것

이미 나온 패턴을 다른 API로 넓히는 것부터 시작한다. 같은 원인이 확인되면 새 제보 대신 기존 제보에 추가한다.

| 우선 | 확인할 것 | 연결 |
| --- | --- | --- |
| 높음 | 국내_차트(일), 해외_차트(분·일)의 실제 `req_qty` 상한 | NH-001 |
